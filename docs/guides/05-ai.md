# 이은석 — AI 기능

> 먼저 [공통 가이드](00-common.md)를 읽으세요.

## 담당 범위
GPT 연동 · 회의록 요약 · 결정사항 추출 · **AI Action Item 생성**

## 담당 파일
| 파일 | 내용 |
|------|------|
| `backend/app/routes/ai.py` | 분석 / Action Item |
| `backend/app/services/ai_service.py` | ← 구현 |
| `backend/app/utils/openai_client.py` | OpenAI 클라이언트 (완성됨) |
| `frontend/src/app/(dashboard)/minutes/[id]/` | AI 분석 결과 표시 |

## 관련 테이블
`ai_summaries`(분석 결과), `action_items`(자동 생성 업무), 입력은 `meeting_minutes`

## 구현 순서
1. **회의록 분석** (`ai_service.analyze`)
   - `minute_id`로 회의록 `content` 조회
   - GPT 호출 → **요약 / 핵심논의 / 결정사항 / 위험요소** 추출
   - `ai_summaries`에 저장 (`summary`, `key_points`, `decisions`, `risks` — jsonb)
2. **Action Item 생성** (`generate_action_items`)
   - 회의록 → GPT → `[{담당자, 업무, 마감일}]` 추출
   - `action_items`에 `status='TODO'`로 저장 (PRD §11 예시 참고)
3. **분석 결과 조회** (`get_summary`)

## OpenAI 호출 예시
```python
from app.utils.openai_client import get_openai

client = get_openai()
resp = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "system", "content": "회의록을 분석해 JSON으로 요약/핵심논의/결정사항/위험요소를 반환."},
        {"role": "user", "content": minute_content},
    ],
    response_format={"type": "json_object"},
)
result = resp.choices[0].message.content  # JSON 문자열 → 파싱
```

## Action Item 추출 형식 (PRD §11)
입력: "김승현 API 설계 진행 6월 15일까지 완료"
출력:
```json
{ "assignee": "김승현", "task": "API 설계", "due_date": "2026-06-15", "status": "TODO" }
```

## 체크포인트
- [ ] GPT 응답이 항상 파싱 가능한 JSON인가? (`response_format` 사용 + 예외 처리)
- [ ] 담당자 이름을 실제 `users`/`company_members`와 매칭하는가?
- [ ] 마감일이 날짜 형식으로 정규화되는가?
- [ ] API 키가 코드에 하드코딩되지 않았는가? (`.env`만)

## 힌트
- 프롬프트에 출력 JSON 스키마를 명시하면 파싱 안정성↑
- 담당자 매칭은 우선 이름 문자열로, 나중에 ID 매핑으로 고도화
- 비용/속도: 학습은 `gpt-4o-mini`로 충분
- 실패 대비: GPT 오류 시 사용자에게 명확한 에러 반환(빈 결과 저장 금지)
